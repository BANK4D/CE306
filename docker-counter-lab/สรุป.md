## 1. วัตถุประสงค์

1.  ทดลองสร้างและเรียกใช้งานแอปพลิเคชันด้วย Docker Compose
2.  ตรวจสอบสถานะการทำงานของบริการด้วย Healthcheck
3.  ใช้ Redis จัดเก็บจำนวนผู้เข้าชม
4.  แยกจำนวนผู้เข้าชมของ 2 กลุ่มด้วย Redis key คนละชื่อ โดยใช้ Redis service และ
    Named Volume ร่วมกัน
5.  ทดสอบการคงอยู่ของข้อมูลหลังหยุดและเริ่ม Container ใหม่

## 2. ไฟล์ที่ใช้ในโปรเจกต์

โปรเจกต์ประกอบด้วยไฟล์หลัก 5 ไฟล์ ได้แก่

-   `app.py` --- โปรแกรมเว็บเซิร์ฟเวอร์และการนับจำนวนผู้เข้าชม
-   `requirements.txt` --- รายการไลบรารีที่ต้องติดตั้ง
-   `.dockerignore` --- ระบุไฟล์หรือโฟลเดอร์ที่ไม่ต้องการส่งเข้า Docker build
    context
-   `Dockerfile` --- คำสั่งสำหรับสร้าง Docker Image
-   `compose.yaml` --- กำหนดบริการ web, web-b, redis และ Named Volume

## 3. Assignment 1: Healthcheck และการจัดเก็บข้อมูล

### 3.1 การตั้งค่า

กำหนดบริการ `web` ให้รอ `redis` จนกว่าจะมีสถานะ Healthy ด้วย `depends_on` และ
`condition: service_healthy` พร้อมกำหนด Healthcheck ให้บริการเว็บและ Redis

บริการ Redis ใช้ Image `redis:7.4-alpine` และจัดเก็บข้อมูลไว้ใน Named Volume ชื่อ
`counter-data` ซึ่งเชื่อมกับ `/data` ภายใน Container

### 3.2 ผลการทดสอบ

จากผลการทำงานที่ตรวจสอบใน Terminal พบว่า

-   Docker Image `ce-counter:lab` สร้างสำเร็จ
-   Container ของ Redis แสดงสถานะ `healthy`
-   Container ของ Web แสดงสถานะ `healthy`
-   เรียก `http://localhost:8080/health` แล้วได้รับผล `{"status":"ok"}`
-   คำสั่งตรวจ Redis key `visits` แสดงค่า `4` ในช่วงเวลาที่ทดสอบ

**ผลการทดสอบ Persistence:**\
ผลที่ตรวจหลังใช้คำสั่ง `docker compose down` และ `docker compose up -d`:

-   ค่า `visits` ก่อนหยุดระบบ: ....................
-   ค่า `visits` หลังเริ่มระบบใหม่: ....................
-   สรุปผล: ....................................................

## 4. Assignment 2: แยกจำนวนผู้เข้าชมสำหรับ 2 กลุ่ม

### 4.1 การแก้ไข app.py

กำหนดตัวแปรสำหรับเลือก Redis key จาก Environment Variable โดยมีค่าเริ่มต้นเป็น
`visits`

``` python
counter_key = os.getenv("COUNTER_KEY", "visits")
```

จากนั้นใช้ตัวแปรดังกล่าวในการเพิ่มจำนวนผู้เข้าชม

``` python
count = store.incr(counter_key)
```

### 4.2 การกำหนดบริการใน compose.yaml

กำหนดบริการเว็บ 2 ตัว โดยใช้ Image เดียวกันและเชื่อมต่อ Redis service เดียวกัน

  รายการ          กลุ่ม A        กลุ่ม B
  --------------- ------------ ------------
  Service         `web`        `web-b`
  พอร์ตบนเครื่อง     `8080`       `8081`
  APP_LABEL       `Group A`    `Group B`
  COUNTER_KEY     `visits:a`   `visits:b`
  Redis service   `redis`      `redis`

ทั้งสองบริการใช้ Named Volume `counter-data` ผ่าน Redis service ร่วมกัน แต่ใช้
Redis key คนละชื่อเพื่อแยกจำนวนผู้เข้าชม

### 4.3 ผลการทดสอบ

-   กลุ่ม A เข้าใช้งานผ่าน `http://localhost:8080`
-   กลุ่ม B เข้าใช้งานผ่าน `http://localhost:8081`
-   ตรวจจำนวนผู้เข้าชมของแต่ละกลุ่มด้วยคำสั่ง

``` powershell
docker compose exec redis redis-cli GET visits:a
docker compose exec redis redis-cli GET visits:b
```

**บันทึกผลการทดสอบจริง**

-   ค่า `visits:a` หลังทดสอบ: ....................
-   ค่า `visits:b` หลังทดสอบ: ....................
-   ผลหลังหยุดและเริ่มระบบใหม่: ....................
-   สรุปว่าข้อมูลของทั้งสองกลุ่มแยกจากกันและยังคงอยู่หรือไม่: ....................

## 5. คำสั่งที่ใช้ในการตรวจสอบ

``` powershell
docker compose config --quiet
docker compose up -d --build
docker compose ps
curl.exe http://localhost:8080/health
docker compose exec redis redis-cli GET visits
docker compose exec redis redis-cli GET visits:a
docker compose exec redis redis-cli GET visits:b
docker compose down
docker compose up -d
```

## 6. หลักฐานประกอบรายงาน

โปรดแทรกภาพหน้าจอผลการทดสอบจริงในหัวข้อต่อไปนี้

1.  ภาพ `docker compose ps` ที่แสดงสถานะของ Container
2.  ภาพผลการเรียก Health endpoint ของ Assignment 1
3.  ภาพผลการตรวจ Redis key `visits` และผลทดสอบ Persistence
4.  ภาพหน้าเว็บกลุ่ม A ที่พอร์ต 8080
5.  ภาพหน้าเว็บกลุ่ม B ที่พอร์ต 8081
6.  ภาพผล `GET visits:a` และ `GET visits:b`
7.  ภาพผลหลังหยุดและเริ่มระบบใหม่เพื่อยืนยัน Persistence ของ Assignment 2

## 7. สรุป

การปฏิบัติงานนี้เป็นการทดลองใช้งาน Docker Compose ร่วมกับ Redis
โดยเริ่มจากการกำหนดบริการเว็บและฐานข้อมูล การตรวจสอบสถานะด้วย Healthcheck
และการจัดเก็บข้อมูลด้วย Named Volume จากนั้นปรับโปรแกรมให้เลือก Redis key ผ่าน
Environment Variable เพื่อให้บริการเว็บ 2 กลุ่มใช้ Redis
ร่วมกันได้โดยแยกจำนวนผู้เข้าชมออกจากกัน

ก่อนส่งรายงาน ควรกรอกผลทดสอบจริงในช่องว่างและแนบภาพหน้าจอให้ครบถ้วน
เพื่อให้รายงานตรงกับผลการทดลองที่ดำเนินการจริง
